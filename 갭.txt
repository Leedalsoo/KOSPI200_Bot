## PART A — 9개 Track 전수 대조 (표 vs 실제 코드)

## PART B — (PART A의 불일치가 전부 해소/확인된 이후에만) 갭상승 통합 컨트롤 로직 설계

전제 위에 시스템을 짓는 것이므로, 이 게이트는 예외 없이 지킨다.

### 설계 목표
지금까지 개별 Track에 흩어져 각자 튜닝되어 온 갭상승 대응 로직을, 다음 원칙을
따르는 **하나의 조율 계층(Gap Control Layer)**으로 재설계한다. 단, 각 Track의
개별 전략 로직(A7, R5, Candidate D, T7-20, Strike Rebuild 등)은 그대로 두고,
그 위에 다음 기능을 추가하는 방식으로 설계한다 (Track 내부를 갈아엎지 않음):

1. **갭 크기 구간 분류 공통 기준**: 지금 Track마다 제각각인 갭 감지 기준을
   통일된 구간(예: 소형 0.3~0.5%, 중형 0.8~1.2%, 대형 1.5%+, 블랙스완 3%+)
   으로 표준화하고, 각 Track이 이 공통 분류 결과를 참조하도록 설계한다
   (각 Track이 독자적으로 다시 계산하지 않도록).
2. **09:00:00 단일가 이벤트 기준 실행 정밀도**: 갭 관련 판단/주문이 "다음
   tick 반응"이 아니라 시가 형성 이벤트 자체와 동일 처리 사이클 내에서
   실행되도록 하는 구조를 설계한다. Virtual Clock/Replay 감사에서 확정한
   이벤트 큐 기반 원칙(대기 없이 즉시 처리)을 그대로 따른다.
3. **Track 간 충돌 중재**: PART A-6에서 발견된 겹침/충돌 지점이 있다면,
   어느 Track이 우선하는지 또는 어떻게 조정되는지 명시적 규칙을 설계한다
   (Risk 감사에서 다룬 Emergency Stop, Hedge Decision 우선순위 원칙과 연결).
4. **갭 포착률(Gap Capture Rate) 측정 지표**: 갭 발생일마다 "이론상 최대
   포착 가능 이익 대비 실제 포착 비율"을 Track별 + 전체 통합으로 계산하는
   측정 모듈을 설계한다. 이는 Logging/Audit 감사에서 확정한 표준 스키마와
   correlation ID 체계를 그대로 활용한다.
5. **오버피팅 방지 검증 계획**: 이 컨트롤 로직이 특정 과거 사례(예:
   2025-01-14 Group 0012) 하나에만 맞춰지지 않도록, PHASE 25에서 사용한
   것과 동일한 방식(다중 시드, 다중 기간, 다양한 갭 크기 분포)으로 검증할
   계획을 설계에 포함한다.
6. **Decision/Execution 분리 유지**: Gap Control Layer는 "판단"만 하고,
   실제 주문은 기존 Broker Interface를 통해서만 나가도록 설계한다. Strategy/
   Track 코드 안에 새로운 직접 주문 경로를 만들지 않는다.

### 설계 산출물
1. Gap Control Layer 아키텍처 다이어그램 (기존 9개 Track과의 관계 포함)
2. 갭 구간 분류 기준표 및 각 Track의 현재 기준과의 매핑/차이
3. 이벤트 처리 순서 설계 (가격갱신 → 구간분류 → Track별 Hedge Decision →
   충돌 중재 → Order Request → Broker)
4. Track 간 충돌 중재 규칙 (해당하는 경우)
5. 갭 포착률 측정 모듈 설계 (데이터 소스, 계산식, 리포팅 방식)
6. 오버피팅 방지 검증 계획
7. 기존 Track 코드 중 이 설계와 충돌/중복되는 부분 목록 (예: Track 5 "데일리
   갭 프로토콜"이 이미 유사 기능을 수행 중이라면 중복 여부 판정)

이 PART B는 **설계 문서만 작성하고 코드를 구현하지 않는다.**
